1. Architecture Overview

The system trains a PPO policy to navigate point robots to goals while avoiding obstacles in a 2D world. Four training modes are compared as an ablation study:

Mode CBF Filter CBF Reward
naive ✗ ✗
reward_only ✗ ✓
filter_only ✓ ✗
cbf ✓ ✓

Training uses rsl-rl (Rudin et al., 2022), a robotics-oriented PPO library that expects a vectorized environment (VecEnv) returning flat PyTorch tensors. The environment is implemented in nav_env/unified_navigation_env.py as UnifiedNavigationEnv, which extends rsl_rl.env.vec_env.VecEnv.

2. Parallelized State Representation

2.1 Indexing Convention

Two levels of parallelism coexist:

P = _num_parallel_envs   (independent "worlds", e.g. 4096)
A = num_agents           (robots per world, e.g. 1–5)
N = P × A                (virtual envs — rsl-rl's view)

Every per-agent tensor lives in shape (P, A, ...):

_robot_pos          : (P, A, 2)   — each agent's [x, y] position
_goal_pos           : (P, A, 2)   — each agent's goal [x, y]
_robot_vel          : (P, A, 2)   — current velocity (dynamic model only)
_obstacle_positions : (P, O, 2)   — obstacles shared within a world
_obstacle_radii     : (P, O)      — radii per obstacle per world

When rsl-rl calls step(action), it passes actions of shape (N, 2) = (P×A, 2). The environment reshapes to (P, A, 2), processes each agent, then flattens results back to (N, ...) before returning. This allows massive throughput by running thousands of worlds simultaneously on GPU.

2.2 Virtual Environment Indexing

Virtual environment index vi = e*A + a corresponds to agent a in parallel world e. This means:

  • Agents within the same world share _obstacle_positions[e]
  • Rewards, terminations, and observations are all indexed by vi from rsl-rl's perspective

2.3 World vs Agent Episodes

Two boolean buffers enable staggered multi-agent termination:

_world_agents_done_buf   : (P, A) bool — agent finished, world episode still running
_agents_reached_goal_buf : (P, A) bool — agent reached its goal this episode

An agent that finishes early is frozen: it receives zero action, stays in place, and does not accumulate reward or step count. The world episode ends when all agents individually finish or any agent fails (collision or timeout). This design avoids penalizing surviving agents for another agent's early failure.

3. Dynamics Models

The dynamics model is set via --dynamics_model at training time and stored in env_meta.json.

3.1 Quasi-Static (Single Integrator)

The robot state is position only. The policy outputs a velocity command directly.

xt+1=xt+(ut+ϵt) Δt\mathbf{x}_{t+1} = \mathbf{x}_t + \bigl(\mathbf{u}_t + \boldsymbol{\epsilon}_t\bigr)\,\Delta t xt+1​=xt​+(ut​+ϵt​)Δt

where:

  • xt∈R2\mathbf{x}_t \in \mathbb{R}^2xt​∈R2 — robot position
  • ut∈[−vmax⁡,vmax⁡]2\mathbf{u}_t \in [-v_{\max}, v_{\max}]^2ut​∈[−vmax​,vmax​]2 — clipped velocity command (vmax⁡=1.0v_{\max} = 1.0vmax​=1.0 m/s)
  • ϵt\boldsymbol{\epsilon}_tϵt​ — additive actuation noise (see Section 6)
  • Δt=0.05\Delta t = 0.05Δt=0.05 s

This is a relative-degree-1 system: the control input u\mathbf{u}u appears in x˙\dot{\mathbf{x}}x˙ directly, so a standard CBF constraint applies without needing the Hessian.

3.2 Dynamic (Double Integrator)

The robot state is position and velocity. The policy outputs an acceleration command.

vt+1=clip⁡ ⁣(vt+(at+ϵt) Δt,  ±vmax⁡)\mathbf{v}_{t+1} = \operatorname{clip}\!\bigl(\mathbf{v}_t + (\mathbf{a}_t + \boldsymbol{\epsilon}_t)\,\Delta t,\; \pm v_{\max}\bigr) vt+1​=clip(vt​+(at​+ϵt​)Δt,±vmax​)

xt+1=xt+vt+1 Δt\mathbf{x}_{t+1} = \mathbf{x}_t + \mathbf{v}_{t+1}\,\Delta t xt+1​=xt​+vt+1​Δt

where:

  • vt∈R2\mathbf{v}_t \in \mathbb{R}^2vt​∈R2 — robot velocity
  • at∈[−amax⁡,amax⁡]2\mathbf{a}_t \in [-a_{\max}, a_{\max}]^2at​∈[−amax​,amax​]2 — clipped acceleration command (amax⁡=2.0a_{\max} = 2.0amax​=2.0 m/s²)
  • vmax⁡=1.0v_{\max} = 1.0vmax​=1.0 m/s (velocity saturation)

This is a relative-degree-2 system: the control a\mathbf{a}a appears in x¨\ddot{\mathbf{x}}x¨, not x˙\dot{\mathbf{x}}x˙. The robot has inertia and cannot stop instantly, making safety significantly harder. The CBF filter must account for the Hessian of the barrier function (see Section 4.4).

4. CBF Safety Framework

Control Barrier Functions (CBFs) provide a formal safety certificate and an efficient real-time filter that modifies unsafe policy actions into safe ones.

4.1 Barrier Function

For each static obstacle iii at position oi\mathbf{o}_ioi​ with radius rir_iri​, define the signed distance barrier:

hi(x)=∥x−oi∥−(rrobot+ri)h_i(\mathbf{x}) = \|\mathbf{x} - \mathbf{o}_i\| - (r_\text{robot} + r_i) hi​(x)=∥x−oi​∥−(rrobot​+ri​)

For the four walls of the world (size LLL):

hleft=x−rrobot,hright=(L−x)−rroboth_\text{left} = x - r_\text{robot}, \quad h_\text{right} = (L - x) - r_\text{robot} hleft​=x−rrobot​,hright​=(L−x)−rrobot​

hbottom=y−rrobot,htop=(L−y)−rroboth_\text{bottom} = y - r_\text{robot}, \quad h_\text{top} = (L - y) - r_\text{robot} hbottom​=y−rrobot​,htop​=(L−y)−rrobot​

The composite barrier is the most critical (minimum) active constraint:

h(x)=min⁡ ⁣(min⁡ihi(x),  hleft,  hright,  hbottom,  htop)h(\mathbf{x}) = \min\!\Bigl(\min_i h_i(\mathbf{x}),\; h_\text{left},\; h_\text{right},\; h_\text{bottom},\; h_\text{top}\Bigr) h(x)=min(imin​hi​(x),hleft​,hright​,hbottom​,htop​)

Interpretation:

  • h>0h > 0h>0 — robot is in the safe region
  • h=0h = 0h=0 — robot is on the safety boundary
  • h<0h < 0h<0 — robot has penetrated an obstacle or wall (unsafe)

4.2 Gradient of the Active Constraint

Only the gradient of the most critical constraint is used (the one achieving the minimum hhh):

Obstacle (closest obstacle o∗\mathbf{o}^*o∗):

∇h=x−o∗∥x−o∗∥\nabla h = \frac{\mathbf{x} - \mathbf{o}^*}{\|\mathbf{x} - \mathbf{o}^*\|} ∇h=∥x−o∗∥x−o∗​

(unit vector pointing from obstacle center to robot)

Wall (e.g., left wall):

∇h=[1, 0]⊤\nabla h = [1,\, 0]^\top ∇h=[1,0]⊤

(outward normal of the closest wall face)

4.3 Quasi-Static Filter (Relative Degree 1)

For x˙=u\dot{\mathbf{x}} = \mathbf{u}x˙=u (single integrator), the time derivative of the barrier is:

h˙=∇h⋅u\dot{h} = \nabla h \cdot \mathbf{u} h˙=∇h⋅u

The CBF condition requires h˙+αh≥0\dot{h} + \alpha h \geq 0h˙+αh≥0 for some class-K\mathcal{K}K function α>0\alpha > 0α>0 (here α=1\alpha = 1α=1):

∇h⋅u+α h≥0\nabla h \cdot \mathbf{u} + \alpha\, h \geq 0 ∇h⋅u+αh≥0

Given the policy's desired control u∗\mathbf{u}^*u∗, define:

ψ=∇h⋅u∗+α h\psi = \nabla h \cdot \mathbf{u}^* + \alpha\, h ψ=∇h⋅u∗+αh

If ψ≥0\psi \geq 0ψ≥0, the desired control is already safe — no modification needed.

If ψ<0\psi < 0ψ<0, the minimum-norm correction is applied (closed-form QP solution):

usafe=u∗−ψ∥∇h∥2 ∇h\mathbf{u}_\text{safe} = \mathbf{u}^* - \frac{\psi}{\|\nabla h\|^2}\,\nabla h usafe​=u∗−∥∇h∥2ψ​∇h

This is the projection of u∗\mathbf{u}^*u∗ onto the half-space {u:∇h⋅u+αh≥0}\{\mathbf{u} : \nabla h \cdot \mathbf{u} + \alpha h \geq 0\}{u:∇h⋅u+αh≥0}, minimizing deviation from the policy's intent.

4.4 Dynamic Filter (Relative Degree 2)

For x¨=a\ddot{\mathbf{x}} = \mathbf{a}x¨=a (double integrator), hhh has relative degree 2 — we must differentiate twice before the control a\mathbf{a}a appears. Define the composite barrier:

ψ1=∇h⋅v+h\psi_1 = \nabla h \cdot \mathbf{v} + h ψ1​=∇h⋅v+h

The exponential CBF condition requires ψ˙1+ψ1≥0\dot{\psi}_1 + \psi_1 \geq 0ψ˙​1​+ψ1​≥0. Expanding:

ψ˙1=∇h⋅a+v⊤∇2h v+∇h⋅v\dot{\psi}_1 = \nabla h \cdot \mathbf{a} + \mathbf{v}^\top \nabla^2 h\, \mathbf{v} + \nabla h \cdot \mathbf{v} ψ˙​1​=∇h⋅a+v⊤∇2hv+∇h⋅v

The full constraint:

∇h⋅a⏟control+v⊤∇2h v⏟Hessian term+2(∇h⋅v)+h⏟state terms≥0\underbrace{\nabla h \cdot \mathbf{a}}_{\text{control}} + \underbrace{\mathbf{v}^\top \nabla^2 h\, \mathbf{v}}_{\text{Hessian term}} + \underbrace{2(\nabla h \cdot \mathbf{v}) + h}_{\text{state terms}} \geq 0 control∇h⋅a​​+Hessian termv⊤∇2hv​​+state terms2(∇h⋅v)+h​​≥0

Hessian-velocity term for obstacle constraints (walls have zero Hessian since hhh is linear):

v⊤∇2h v=∥v∥2−(∇h⋅v)2d\mathbf{v}^\top \nabla^2 h\, \mathbf{v} = \frac{\|\mathbf{v}\|^2 - (\nabla h \cdot \mathbf{v})^2}{d} v⊤∇2hv=d∥v∥2−(∇h⋅v)2​

where d=∥x−o∗∥d = \|\mathbf{x} - \mathbf{o}^*\|d=∥x−o∗∥ is the distance to the active obstacle. This is the curvature of the signed-distance function on a circle.

Define the slack of the desired acceleration a∗\mathbf{a}^*a∗:

slack=∇h⋅a∗+v⊤∇2h v+2(∇h⋅v)+h\text{slack} = \nabla h \cdot \mathbf{a}^* + \mathbf{v}^\top \nabla^2 h\, \mathbf{v} + 2(\nabla h \cdot \mathbf{v}) + h slack=∇h⋅a∗+v⊤∇2hv+2(∇h⋅v)+h

If slack≥0\text{slack} \geq 0slack≥0, no modification. If slack<0\text{slack} < 0slack<0, minimum-norm correction:

asafe=a∗−slack∥∇h∥2 ∇h\mathbf{a}_\text{safe} = \mathbf{a}^* - \frac{\text{slack}}{\|\nabla h\|^2}\,\nabla h asafe​=a∗−∥∇h∥2slack​∇h

5. Multi-Agent Extension

5.1 Agent-Agent Safety via Extended Obstacle Set

During step(), each agent's CBF filter sees both static obstacles and other agents as dynamic obstacles. The obstacle set is extended on the fly:

ext_obs_pos   = cat([static_obstacles,      other_agent_positions], dim=1)
ext_obs_radii = cat([static_obstacle_radii, robot_radius * ones(A-1)], dim=1)

The CBF filter then treats agent-agent proximity identically to agent-obstacle proximity, using rrobotr_\text{robot}rrobot​ as each other agent's radius. This means the inter-agent collision threshold is 2rrobot2r_\text{robot}2rrobot​.

Note: This is a per-agent filter — each agent independently solves its own minimum-norm QP. There is no joint multi-agent safety guarantee; agent aaa's filter corrects aaa's action but does not account for simultaneous corrections by other agents.

5.2 Frozen Agents During Multi-Agent Episodes

When an agent individually terminates (goal reached, collision, or timeout), it is marked frozen. On subsequent steps:

  • Its action is set to zero
  • Its position is not updated
  • It is excluded from the collision check (frozen agents are ignored in agent-agent collision detection)
  • Its elapsed step count does not increment

The world episode continues until all other agents finish or any active agent fails.

5.3 Multi-Agent Observation Space

Each virtual env (one agent's view) observes:

Component Dim Description
goal_pos 2 Own goal position [x, y]
last_velocity 2 Own velocity [vx, vy]
obstacles 3 Closest static obstacle [x, y, r]
other_agents (A−1) × 3 Other agents' positions and radii [x, y, r_robot]
robot_pos 2 Own position [x, y]

Total observation dimension: 2+2+3+(A−1)×3+2=9+(A−1)×32 + 2 + 3 + (A-1) \times 3 + 2 = 9 + (A-1) \times 32+2+3+(A−1)×3+2=9+(A−1)×3

For example:

  • A=1: 9+0=99 + 0 = 99+0=9 (no other_agents key)
  • A=3: 9+6=159 + 6 = 159+6=15
  • A=5: 9+12=219 + 12 = 219+12=21

Keys are sorted alphabetically before concatenation for a consistent flat vector ordering. Only the closest static obstacle is included (3 dims fixed), not all OOO obstacles — this keeps obs size independent of num_obstacles.

The other_agents component is the key addition for multi-agent: each agent perceives the other agents as dynamic circular obstacles, enabling coordination (or at least collision avoidance) through the policy.

6. Stochastic Control Noise

Three noise levels inject additive Gaussian noise after the CBF filter, simulating actuator uncertainty for robustness ablation studies:

Level Std (fraction of max control)
low 0.1
medium 0.3
high 0.5

Quasi-static: noise on velocity command

uexecuted=usafe+ϵ,ϵ∼N(0, (σlevel⋅vmax⁡)2I2)\mathbf{u}_\text{executed} = \mathbf{u}_\text{safe} + \boldsymbol{\epsilon}, \quad \boldsymbol{\epsilon} \sim \mathcal{N}(0,\, (\sigma_\text{level} \cdot v_{\max})^2 I_2) uexecuted​=usafe​+ϵ,ϵ∼N(0,(σlevel​⋅vmax​)2I2​)

Dynamic: noise on acceleration command

aexecuted=asafe+ϵ,ϵ∼N(0, (σlevel⋅amax⁡)2I2)\mathbf{a}_\text{executed} = \mathbf{a}_\text{safe} + \boldsymbol{\epsilon}, \quad \boldsymbol{\epsilon} \sim \mathcal{N}(0,\, (\sigma_\text{level} \cdot a_{\max})^2 I_2) aexecuted​=asafe​+ϵ,ϵ∼N(0,(σlevel​⋅amax​)2I2​)

The filter runs before noise injection. This is important: with filter_only, the filter produces a safe action in expectation, but the noise may still push the robot into an unsafe state. Higher noise levels thus test the limits of CBF-only safety.

There is also a legacy noise_level = 0.1 term (always active) that adds unconditional velocity-scale noise. The control_noise_std is additive on top of this.

7. Reward Function

For each virtual env (agent) at each step, the total reward is:

r=rgoal+rcollision+rwall+rprogress+rstep+rtimeout+rcbfr = r_\text{goal} + r_\text{collision} + r_\text{wall} + r_\text{progress} + r_\text{step} + r_\text{timeout} + r_\text{cbf} r=rgoal​+rcollision​+rwall​+rprogress​+rstep​+rtimeout​+rcbf​

Goal reached +1+1+1

7.2 Progress Reward (Dense Shaping)

rprogress=20⋅dt−1−dtvmax⁡⋅Δt⋅1[active]r_\text{progress} = 20 \cdot \frac{d_{t-1} - d_t}{v_{\max} \cdot \Delta t} \cdot \mathbf{1}[\text{active}] rprogress​=20⋅vmax​⋅Δtdt−1​−dt​​⋅1[active]

where dt=∥xt−g∥d_t = \|\mathbf{x}_t - \mathbf{g}\|dt​=∥xt​−g∥ is current distance to goal. The denominator normalizes by the maximum possible progress per step, so reward ≈ +20+20+20 when moving directly toward the goal at maximum speed.

7.3 Step Penalty

rstep=−0.01⋅1[active]r_\text{step} = -0.01 \cdot \mathbf{1}[\text{active}] rstep​=−0.01⋅1[active]

Encourages faster task completion.

7.4 CBF Reward Components (only when use_cbf_reward_penalty=True)

Action alignment penalty: Penalizes how much the filter had to correct the raw policy action.

raction=100[exp⁡ ⁣(−∥u∗−usafe∥20.25)−1]⋅1[active]r_\text{action} = 100 \left[\exp\!\left(-\frac{\|\mathbf{u}^* - \mathbf{u}_\text{safe}\|^2}{0.25}\right) - 1\right] \cdot \mathbf{1}[\text{active}] raction​=100[exp(−0.25∥u∗−usafe​∥2​)−1]⋅1[active]

  • No correction needed: raction=0r_\text{action} = 0raction​=0
  • Large correction: raction→−100r_\text{action} \to -100raction​→−100

This incentivizes the policy to learn actions that are natively safe, reducing reliance on the filter.

Constraint violation penalty:

rψ=10⋅min⁡(ψ, 0)⋅1[active]r_\psi = 10 \cdot \min(\psi,\, 0) \cdot \mathbf{1}[\text{active}] rψ​=10⋅min(ψ,0)⋅1[active]

Directly penalizes the CBF slack ψ\psiψ when negative (i.e., when the unfiltered action was unsafe). This is excluded from the logged reward to avoid confounding evaluation metrics.

8. Placement Algorithm

World initialization uses a two-level retry to handle crowded configurations (many agents, many obstacles in a bounded world).

Algorithm

For each parallel world e:
    For up to 20 obstacle placement attempts:
        Sample O obstacle positions
        Check: obstacles within world bounds
        Check: obstacles separated from each other (min clearance)

        all_placed = True
        For each agent a in 0..A-1:
            agent_placed = False
            For up to 50 agent placement attempts:
                Sample robot start position
                Sample goal position
                Check: robot not overlapping any obstacle
                Check: robot not overlapping other agents already placed
                Check: goal not overlapping any obstacle
                Check: robot-goal separation > min threshold
                If all checks pass → mark agent_placed = True; break
            If not agent_placed:
                all_placed = False; break  ← retry obstacle layout

        If all_placed:
            Return (obstacle_positions, robot_starts, goal_positions)

    Return None → fallback to evenly spaced grid positions

Motivation for Two-Level Retry

With A=5 agents, an all-or-nothing 100-attempt strategy has exponential failure probability: if each agent placement independently fails with probability ppp, placing all A agents succeeds with probability (1−p)A(1-p)^A(1−p)A. With p=0.3 and A=5 this is only ~17%. The two-level retry retries only the per-agent placement inner loop, keeping successful obstacle layouts fixed. This dramatically reduces placement failures without loosening safety constraints or altering the statistical distribution of valid layouts.

9. Training Pipeline

9.1 PPO via rsl-rl

The policy is trained with Proximal Policy Optimization (Schulman et al., 2017) using the rsl-rl runner:

  • Parallel worlds: num_envs = 4096 × A agents = 4096A virtual environments
  • Rollout horizon: 48 steps per env per iteration
  • Mini-batch training: 10 learning epochs, 8 mini-batches per epoch
  • Policy architecture: MLP with [obs_dim → 32 → 32 → 2], ReLU activations
  • Critic: separate MLP [obs_dim → 32 → 32 → 1]
  • PPO clip parameter: 0.2
  • Discount: γ = 0.99, GAE λ = 0.95
  • Learning rate: 3×10⁻⁴ (fixed schedule)
  • Entropy coefficient: 0.005
  • Max iterations: 1500

9.2 Environment Meta File

train.py writes env_meta.json to the run directory after the runner is initialized. This captures all environment parameters including:

{
    "env": "cbf",
    "num_agents": 5,
    "num_obstacles": 0,
    "dynamics_model": "dynamic",
    "control_noise": "medium",
    "use_cbf_action_filtering": true,
    "use_cbf_reward_penalty": true,
    ...
}

At test time, test.py reads this file to reconstruct the exact same environment. Critically, num_obstacles and num_agents are resolved from env_meta.json rather than config defaults — without this, the loaded policy's expected observation size would mismatch the reconstructed environment.

9.3 Experiment Grid

The full training grid (68 experiments) is defined in submit_training_grid.sh:

  • Suite 1 (8): 4 training types × {quasi_static, dynamic}
  • Suite 2 (60): 4 training types × 5 agent/obstacle configs (A+O=5) × 3 noise levels × dynamic only

The SLURM array submission uses one GPU job per experiment, each writing to logs/<experiment_name>/<run_name>/<timestamp>/. Evaluation is batched by submit_eval_grid.sh, which scans the logs directory and runs the appropriate test wrapper script for each trained run.
